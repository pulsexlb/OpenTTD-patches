# 有候选目标但进路受阻时的连接方向查询卡顿

## 新存档与原因

用户再次提供的“慢车无法等待.sav”修改时间为 2026-11-01 19:02，120 个 NewGRF 全部激活。此前的优化只跳过完全没有合格候选的方向查询；本次候选已经存在，但没有可用进路，因而仍每刻执行双向完整搜索。

128 刻细分重放中，`CheckReverseTrain` 调用 7,730 次，累计约 10.55 秒，占整个模拟约 12.41 秒的大部分。自动待避区域更新约 23 毫秒。不能因此关闭自动待避或放宽连接筛选。

## 修复范围

只调整 `ProcessOrders` 对未变的、尚无目的地的前往连接命令的重复处理：列车已经 Stuck 时，方向复查跟随现有 `path_backoff_interval` 和 `wait_counter` 的 PBS 重试节奏。没有另加按实际时间计算的缓存，没有新存档字段，不减少节点额度，也不改变候选、速度、功率、路签和独占认领规则。

新命令、路点停车出发、未受阻列车及强制前进保留原有立即检查。`Order::Equals` 忽略部分扩展字段，因此另比较连接筛选字段，防止实际条件变化被当作重复命令。等待期间后来出现的目标，按原生重试时机重新寻路，不会永久漏检；响应节奏遵循该存档的 PBS 重试间隔。
