### 0.6 本轮新增（M6/M7 及修复）

- **载体类型收紧**：只有**火车 / 船 / 飞机**能当载体。以前一辆卡车也能"装载"另一辆卡车（并把它从路网上抹掉），现已禁止。
- **被运载车辆在载体被销毁时自动放回路网**：载体被删除/出事时，它载着的卡车会在**载体所在格**恢复可见并继续跑自己的订单，不会凭空消失（也不会留下"孤儿"车辆）。控制台 `rvtransport release <卡车ID>` 走的就是同一条释放路径，便于单独验证。
- **载体可等车**：订单下拉新增 **等待道路载具（Wait for road vehicles）**；打开后载体在该站会一直等到（匹配的）道路载具装上来才发车——语义同 "Full load"。

## 1. 搭一个最小场景（GUI 里操作）

1. 新游戏：地图 256×256 即可，**不要加载 NewGRF**（保持干净），资金选"无限制/高"；
2. 建**一个站**，要求它同时具备：
   - **公路停靠站**（卡车停靠站，港湾式或直通式都行，**直通式更推荐**）；
   - **铁路站台**（紧邻建造，会自动并入同一个车站）；
3. 建**公路车库**买 1 辆卡车；建**铁路车库**买 1 台机车（建议再加 1 节车厢）；
4. 在远处再建**第二个站 B**（同样要带公路停靠站；铁路站台可选）；
5. 排程：
   - 卡车订单：`去车站 A`（Go to）；
   - 火车订单：`去车站 A` → `去车站 B`。

## 2. 在订单窗口里设置"装载/卸载道路载具"（M5 已提供 GUI 入口）

1. 打开车辆订单窗口（点车辆 → "Orders"）；
2. 选中要设置的**去车站**订单；
3. 两个下拉里分别有道路载具相关项（**勾选框**，可以多选，勾选状态会立刻刷新）：

   **装货方式下拉**（平时显示 No loading / Full load 的那个）底部：
   - **Load road vehicles**（对卡车而言：**等待被运载**）— 在该站装载等待的道路载具 / 卡车在此等待被装走；
   - **Only road vehicles for the next stop**（缩进一级）— 只装"目的地就是本车下一站"的道路载具（开启装载时**默认勾上**）；
   - **Wait for road vehicles**（缩进一级，仅载体）— 在该站一直等到有道路载具装上来才发车（语义同 "Full load"，**无限等**）。

   **卸货方式下拉**（平时显示 Unload / Transfer 的那个）底部：
   - **Unload road vehicles**（对卡车而言：**在此被卸下**）— 在该站把载着的道路载具放下 / 卡车在此被放下。

   再点一次同一个勾选框即可取消。取消"装载道路载具"会连带取消它的两个子项（匹配、等待）；勾选匹配或等待时会自动把"装载"一起勾上——这些组合规则都是强制的，不会出现"只勾了匹配却没装车"这种矛盾状态。

   > 提示：卡车自己的订单**不会**出现"只装载前往下一站"这一项（对它没有意义）。旧存档里如果残留了这个位，只要重新勾一次"等待被运载"就会被自动清掉；显示上也会忽略它。
4. 设置好后回到游戏，让车辆按订单跑即可。

**控制台备用方式**（GUI 出问题或想快速验证时）：

```
rvtransport list                          # 看车辆 ID 与状态
rvtransport orderflag <车辆ID> load        # 等价于下拉里的 Load road vehicles
rvtransport orderflag <车辆ID> unload      # 等价于 Unload road vehicles
rvtransport orders <车辆ID>                # 打印每条订单的 RoRo 旗标
rvtransport toggle <车辆ID> <订单序号> load|unload|dest|wait   # 与勾选框完全相同的规则（含连带关系）
rvtransport setflags <车辆ID> <订单序号> <值>                    # 直接把旗标设成某值（便于测试）
rvtransport modify <车辆ID> <订单序号> load|unload|dest|wait     # 走与 GUI 相同的命令路径
```

说明：`orderflag` 会同时写"车辆当前订单"和"订单列表中的当前项"；用 GUI 下拉则直接写订单列表项，更稳。

## 3. 期望现象

| 阶段 | 期望 |
|---|---|
| 订单设置后 | 订单行会**逐项列出**该订单的 RoRo 设置（例如 `去 A 站 装载道路载具 只装载去下一站的道路载具`）；"装货方式"按钮显示"装载道路载具"（卡车显示"等待被运载"），"卸货方式"按钮显示"卸载道路载具"（卡车显示"在此被卸下"） |
| 卡车到达 A 站后 | 卡车**停住不动**（进入"等待被运载"）；`rvtransport state <卡车ID>` 显示 `flags=1`、`stopped=1` |
| 火车到达 A 站后 | 卡车**从路网消失**（画面上看不到它了）；`rvtransport state <卡车ID>` 显示 `flags=2`、`hidden=1`；`rvtransport list` 里火车的 `carrying=1` |
| 给火车打上卸载旗标（`rvtransport orderflag <火车ID> unload`）后火车到达 B 站 | 卡车**出现在 B 站的公路停靠站格**上，随后按自己的订单继续行驶；`rvtransport state <卡车ID>` 显示 `flags=0`、`hidden=0`、`tile` 有效 |
| 全程 | **无崩溃、无断言弹窗**；车辆数量不变（卡车没被销毁/复制） |

## 5. 已知限制（这一阶段属正常现象）

- **目的地匹配已实现**：开启"装载道路载具"时默认同时打开"仅装载开往同一目的地的道路载具"（条件表达式语义：**不匹配即跳过**，载体不会因此永远等下去）。想装任何车就把它关掉；
- **"等待道路载具"是无限等待**（与 "Full load" 同语义、同实现：把 `finished_loading` 压住不发车），引擎里**没有**自动放弃的超时兜底——如果车站里始终没有可装的卡车，载体就会一直停在那里。实操建议：把它和时刻表/其它装货方式配合使用，或只在确定有车可装的车站打开；
- 载体的**卖出保护**：还载着道路载具的载体**不能直接卖出**（会提示"请先卸下所运载的道路载具"）；被运载中的卡车也不能卖（提示"不能出售正在被运载的道路载具"）。要清空载体，请先让它在设了"在此被卸下"的车站把卡车放下；
- 铰接卡车（多节）**已支持**：整段（所有节）一起被运载、一起被卸下，不会被拆开；
- **车辆详情窗口里已有"载运的道路载具"清单**（火车有多一个页签；船/飞机在同一页以可点击的行列出），也可以点行定位到那辆被运载的车；
- **"哪节可以装车"是三档设置**（设置 → 专家设置 → **道路车辆运输** → "道路载具运载：哪些车厢/货舱可以装载道路载具"），**默认第 2 档**：  - 第 2 档（默认）"散货、'超大件'或'运载工具'货物"：只放行货物满足**散货（`Bulk`）**、**`Oversized`**、或**货物标签为 `VEHC`（"Vehicles/运载工具"）**任意一条的节——原版内容下**只有散货车厢（敞车/漏斗车：煤、矿石、谷物、水果、糖、太妃糖）能装车**；木材/钢材/货物/邮件/液体/乘客一律拒绝（**木材车厢、油罐车、客车厢、客机都装不上**）。要玩"汽车渡轮/驮背运输"请挂载提供 `Bulk`/`Oversized`/`VEHC` 类货物的 NewGRF；本回归套件因为测试存档的载体是木材车厢，所以脚本里会先 `setting vehicle.rv_transport_carrier_parts 0` 把门开开，门本身由 `testrun\verify_carrier_parts.ps1` 覆盖。
  - 第 1 档"仅限装载超大件货物的节"：需要提供 oversized 类货物的 NewGRF 才能装；**原版内容没有任何 oversized 货物，选它会导致谁都装不上车**（可用于验证"严格门"行为）。注意 `chinasettrains.grf` 是列车集，不含 oversized 类货物，无法用于第 1 档；
  - 第 0 档"任何具备载货容量的节"：最宽松，客车厢也收车（老版本二值开关打开时的行为，语义等价于旧的"不设门"）。
  - 切换设置**只影响装载判断**，不影响已经在车上的道路载具（它们照常在目的站被卸下），所以中途改设置不会把车丢在路上。
- **总开关**（同一设置页最上面一项 "道路载具运载"）：关闭后**不再发生任何装载**，正在"等待被运载"的车会**结束等待、继续按自己的调度行驶**，而**已经在车上的车仍然可以在目的站被放下**——所以关掉它不会把车卡死在车上（订单设置也不会被改动，重新打开即恢复）。
- **"被运载过久"告警**（同一设置页 → "道路载具运载：被运载的道路载具超过多久未卸下时告警"，默认 **30 天**，0 = 关闭）：道路载具只会在**它自己调度**里标了"在此被卸下"的车站被放下，所以永远不停那种站的载体（或目的站被拆掉的车）会把车一直带在身上——超过阈值就发一条**建议类新闻**（"{车} 已被运载 N 天仍未卸下"）。**每趟只提示一次**，下次再被装上可以再次提示。想看效果：把手测里的阈值调成 1 天，让一辆车被装走后不再经过它声明的卸货站，跑一会儿就会出现该新闻。
- 船 / 飞机作为载体走的是与火车**完全相同**的代码路径（`RVTransportAttachAuto` 只要求 `part->First() == carrier`），但尚未在实机上走查，手测步骤见第 6 节；
- 需要绕过一切检查只验证事务时，仍可用 `rvtransport attach <载体ID> <卡车ID> force`。

## 6. 船 / 飞机载体手测步骤（尚未走查，欢迎帮忙验一下）

前置：新游戏、无 NewGRF、资金无限制；"哪节可以装车"改成**第 0 档**（船的原版货舱装的是普通货物，第 2 档只放行散货/超大件/`VEHC` 货物，第 1 档需要专用 NewGRF；手测时用第 0 档验证机制本身）。

**船：**

1. 挖一条运河（或找一段海），建**一个车站**同时包含：**码头（Dock）** + **公路停靠站**（两者必须在同一车站覆盖范围内，建造时会自动并入同一车站）；
2. 公路车库买 1 辆卡车；船坞买 1 艘**有货舱容量**的船（原版货船即可）；
3. 在运河另一端建第二个车站（同样要有码头 + 公路停靠站）；
4. 排程：卡车 `去车站 A` + 装货方式选 **等待被运载**；船 `去车站 A`（装货方式选 **装载道路载具**）→ `去车站 B`（装货方式选 **在此被卸下**）；
5. 期望：卡车先在 A 站停住 → 船靠泊后卡车消失、`rvtransport list` 显示船的 `carrying=1` → 船到 B 站后卡车出现在 B 站的**公路停靠站格**上并继续跑自己的订单；全程无断言/崩溃。

**飞机：**

1. 建**同一个小机场/直升机坪**，并让**公路停靠站**落在机场车站的覆盖范围内（同一车站）；
2. 买 1 架**有货舱容量**的飞机（原版就有）+ 1 辆卡车；
3. 排程同上（目的地改为第二个带机场的车站）；
4. 期望同上。注意飞机容量按**吨位**算：一架容量小的飞机可能装不下满载的重卡（会被拒绝装载，车辆继续留在站里等待，这是预期行为——请空车或用大容量机型测试）。

**载体被销毁：**

1. 让卡车被装上载体；
2. 触发载体消失：让载体**出事故**（撞车/平交道口）或用场景编辑器/控制台删除它（注意：**车库卖出会被保护拦下**，这是设计如此）；
3. 期望：**被运载的卡车随载体一起消失**（像火车的车厢一样），车辆列表里也不再出现该车；**不会**出现"卡车传送到上一个车站继续跑"的现象。若卡车没有一起消失（或游戏崩溃/断言），请按第 4 节把日志给我。

> 说明：`testrun\verify_release.ps1` 验证的是 `rvtransport release` 这条**手动释放**通道（`RVTransportForceRelease`，现在只用于调试命令与读档兜底）；普通玩法里载体被毁时走的是"一起销毁"（`RVTransportDestroyCarriedVehicles`）。

**多舱段（多节）船：**
JGRPP 允许 NewGRF 船只做成**多节**（每节一个货舱，各自有容量，例如你存档里那艘：第 0 节 720 吨、第 1 节 450 吨）。请单独验一下：

1. 用带多节船的船只集（你本地那局就有）建一条和上面一样的"码头 + 公路停靠站"线路；
2. 让卡车等待被运载，船带着"装载道路载具"的订单靠泊；
3. 期望：**任意一节**都能收车（不再只有第 0 节能收），`rvtransport parts <船>` 会显示某节 `holds_rv=true`；
4. 到对岸后（订单含"卸载道路载具"）：车必须被放下来。**修复前的现象就是这里失败**（车留在船上、永远卸不下来）；
5. 若还有问题，把 `rvtransport list` / `rvtransport parts <船>` / `rvtransport carried <船>` 的输出发我。

**卡车"多段接驳"怎么写调度（重要）：**

一辆卡车可以被运载多次，例如"火车运一段 → 自己开一段 → 船运一段"。规则是：

- 在**每一段的上车站**那条订单上勾 **等待被运载**；
- 在**每一段的下车站**那条订单上勾 **在此被卸下**；
- 卡车被装载时，它的调度会**自动前进到下一条**（也就是那条"在此被卸下"），被运载期间它的当前订单就是"我要在这一站下车"；载体到站时**比对一致才放下**（不一致就继续留在车上，等下一次/下一段）。

例：`2: 直达 A 废车场 等待被运载` → `3: 直达 B 西站 在此被卸下` → `4: 直达 C 西站 等待被运载` → `5: 直达 D 码头 在此被卸下` ✓ 这样火车在 B 站放下、船在 D 码头放下，各管自己那一段。

如果某辆车的调度里**没有**在载体卸货站勾"在此被卸下"（或者你想让载体"全都卸下来"），在**载体的卸货订单**上再勾一个 **卸载所有道路载具**（订单窗口 → 卸货方式那一行的 `道路载具运输…` → 第 5 个勾选框），这样载体到站就把车上所有车都放下来，忽略各自的声明。

排查"为什么它不下车"：控制台 `rvtransport dump`（一次打印每台车、每个载体、逐节容量、声明卸货站，并直接给出"能否卸在此站"的判定与原因），或 `rvtransport orders <卡车id>`（现在会打印每条订单的**目标站编号 + 站名**——界面只显示站名，而两个不同的站可能重名）。

**"放下后看不到车 / 好像卡在站里"的两种常见误会：**

- **游戏处于暂停**：被放下的卡车会停在停车位里、状态是"即将驶离"（`state` 已在驶离值、`speed≈1`）。**取消暂停它就会开走**（实测：暂停状态下载入的 6 辆卡车，跑 9 秒后全部正常行驶并推进了订单）。载具窗口显示的位置仍是那个车站是对的。
- **那一格没被重画**（早期版本的问题，已修）：被隐藏过的车放回路面时，引擎只改了"是否绘制"的内部标记、没把格子标脏，而视口只重画被标脏的格子 → 车其实在跑但画面上看不到。现在装载（消失）/卸载（出现）/释放/回滚四条路径都会把该区域标脏。

## 7. 被运载车辆的可见性与"定位"

- **车辆列表**：被运载的卡车**仍然出现在车辆列表与分组列表里**（状态列显示"正在被运载"），不会被藏起来；
- **定位 / 跟随**：在列表或车辆窗口点"定位车辆"、或双击进入跟随模式时，镜头**跟着它所在的载体**走（而不是停在它被装走的那个车站）；载体开到哪里镜头跟到哪里；
- 载体的状态栏会显示"载有 N 台道路载具"，方便反查；
- **载运清单**：打开**载体的详情窗口**（列车/船/机的"详情"按钮）→
  - **不用翻页就能看到**：详情窗**顶部**（速度/载重那几行下面）会常显一行 `载有 N 台道路载具`，只在载体真的装着车时出现 —— 先看这一行确认"车确实在车上"。
  - **火车**：详情窗现在多了一个 **`载运`页**（标签依次是 `货物 / 信息 / 容量 / 全部货物 / 性能 / 载运`）——这一页**只列车上装着的道路载具**，一车一行（编号+车名、记录重量、货物、声明卸货站），空着时会写"本列车没有载运道路载具"；**点某一行 → 直接打开那辆车的窗口并把镜头带过去** ✓（脚本可用 `rvtransport row <火车id> <行号>` 核对某一行对应哪辆车）。
  - **原来的位置也保留**：切到 **"信息"页**（`货物 / 信息 / 容量 / 全部货物 / 性能`），把列表**滚到底部** —— 在列车自己的车辆之后会多出一段 `载运的道路载具：` + 每台一行；该页的滚动条已经把这几行算进去了（行数记账由 `testrun\verify_details.ps1` 守着）。
  - **船/机**：在详情面板**底部**直接列出（`载运的道路载具：` + 每台一行），**每行同样可点**（点开那辆车的窗口）；装/卸车时窗口高度自动变化，不需要重开窗口。
  - 任何载体都可以用控制台 `rvtransport carried <载体ID>` 精确列出所载车辆（含编号/货物/重量/声明卸货站），脚本化验证用这个。
- **"车装在哪一节"与"为什么某节没变成满载外观"**：控制台 `rvtransport parts <载体ID>` 逐节打印 `cargo=… cap=… stored=… rv_capacity=…t rv_used=…t holds_rv=…`。
  - 一节能不能收车看的是**重量**：`rv_capacity`（= 该节 `cargo_cap` × 该货物每单位重量 ÷ 16）必须 ≥ 车的整备重量。客车按"每人 1/16 吨"折算往往只有几吨，所以**大卡车通常只能上货车**（这也是"卡车在站里等、火车却不停下来装"的常见原因）。
  - 满载外观只对**装了车的那一节**生效；如果那一节的车辆集**没有"空/满载"两套图**（不少客车、部分专用货车就是这样），外观不会变 —— 此时用"载运清单 / `carrying=`"确认功能本身是好的。

## 8. 铰接（多节）道路载具的手测步骤（需要带铰接车的 NewGRF）

原版内容里**没有铰接道路车辆**（铰接客车/铰接卡车都由 NewGRF 提供，例如你本地那份 `chinasetbuses.grf` 中国公交车集）。所以要测这一项，必须用带铰接车的车辆集开一局。

1. 新游戏时加载一个**含铰接道路车辆**的 NewGRF（车辆集）；
2. 建一个带**直通式**公路停靠站的车站（⚠ 引擎本身不允许铰接车进入港湾式停车位：`RoadStop::Enter()` 直接拒绝 `HasArticulatedPart()` 的车，所以铰接车只能在直通站停靠/等待/被放下）；
3. 买一辆**铰接**车（在购买列表里通常是"两节"外观的那种），按第 1–2 节给它排"等待被运载"的订单；火车/船/机照旧设"装载道路载具"；
4. 期望：
   - 铰接车**整挂**被装走（车头与后节一起从路网上消失，画面上都看不到）；
   - 容量判定按**整挂重量**算（`cached_weight` 含所有节），所以一辆满载的铰接车明显比单车"重"；
   - 卸载时整挂落到同一格并**照常散开行驶**（与出库时的行为一致）；
   - 载体被毁时整挂一起消失；`rvtransport state <铰接车ID>` 会逐节打印 `part N: ... hidden=... state=...`，可以确认每一节都被正确隐藏/恢复。

> 若你手头没有方便测试的存档：开一局加载 `chinasetbuses.grf`，买一辆铰接公交并保存到 `build\save\`，我就能把它接进自动化脚本（`verify_articulated.ps1`）逐项断言。

## 9. 条件选择运载（筛选条件）的手测步骤

一条"装载道路载具"的订单可以带**筛选条件**，只有**全部满足**的等待车辆才会被装走，不满足的继续等下一班（语义与"只装载去下一站的道路载具"一致，只是判据变多了）。参考 px-patch"连接车辆"的参数化风格：

| 条件 | 取值 | 含义 |
|---|---|---|
| 载货状态 | 任意 / 空车 / 满载 | 只装空车，或只装满载的车 |
| 货物 | 任意 / 能载某货 / 正载某货 | 只装能载（或正在载）指定货物的车 |
| 最短等待 | 0 = 不限 / N 天 | 只装已经等了 N 天以上的车（避免刚到的车插队） |
| **路签** | 任意 / 某个**道路载具类型**的路签 | 只装**持有该路签**的车（与 px-patch"连接车辆"里的路签同义：槽） |

**控制台操作**（GUI 入口见下一段说明）：

```
rvtransport criteria <载体ID> <订单序号> loadstate any|empty|full
rvtransport criteria <载体ID> <订单序号> cargo any|<货物ID> [carrying]
rvtransport criteria <载体ID> <订单序号> minwait <天数>
rvtransport criteria <载体ID> <订单序号> slot any|<路签ID>
rvtransport mkslot <名字> [占用上限]         # 调试用：建一个道路载具路签
rvtransport slot <车辆ID> <路签ID> on|off     # 调试用：把车辆加入/移出路签
rvtransport sim <载体ID> <道路载具ID>         # 等价于"让这辆车在站里等着 → 按条件扫描 → 装车"
```

`sim` 输出的 `scan found=true/false` 直接告诉你条件是否接受了这辆候选车，`criteria=` 会显示该订单当前是否带了条件；`rvtransport state <车辆ID>` 会列出该车持有的路签。

**订单窗口里的入口**（GUI）：装货方式下拉（以及卸货方式下拉）底部只有**一项** **`道路载具运输…`**，点开是一个独立窗口，所有道路载具相关设置都在这里面（这样下拉本身保持干净）：

| 行 | 说明 |
|---|---|
| **装载道路载具** | 按钮，按下=在该站装载（卡车视角写作"等待被运载"）|
| **只装载去下一站的道路载具** | 按钮，只装目的地=载体下一站的车（开启装载时默认按下）|
| **等待道路载具** | 按钮，在该站等到有车装上来才发车（语义同 Full load，无限等）|
| **卸载道路载具** | 按钮，在该站把载着的车放下（卡车视角写作"在此被卸下"）|
| 载货状态 | 任意 / 仅空车 / 仅满载 |
| 货物 | 任意 / 本局出现过的每种货物 |
| 货物判据 | 能载 / 正载（配合上一行）|
| 最短等待 | 不限 / 1 / 2 / 5 / 10 / 30 / 60 天（控制台设的自定义天数显示为"自定义时间"）|
| 路签 | 任意 / 某个道路载具类型的路签（下拉里显示路签名；**已删除的路签**会显示成"任意"）|
| 最多同时装载 | 不限 / 1 / 2 / 3 / 5 / 10（控制台设的自定义值显示为"最多自定义数量"）|

- 判据下拉只在**勾选了"装载道路载具"**时可用（没装载就没意义）；卡车自己的订单里这几行会灰掉。
- **"最多同时装载"是上限而不是筛选**：载体上**已经载着**的道路载具数量达到该值时就停止继续装（0 = 不限），所以多段行程里在上一站装的车也会计入。判定点在 `RVTransportAttachAuto()`——所有装载都经过它，调试命令也绕不过去。
- **路签判据怎么用**：先在 JGRPP 的路签管理窗口建一个**道路载具**类型的路签（或控制台 `rvtransport mkslot <名字>`），再让卡车用"尝试获取路签"调度拿到它；然后在载体订单上把"路签"设为该路签 —— 这样只有**持有该路签**的车才会被装走（判据就是"候选必须是该路签的占用者"，与 px-patch 连接车辆的路签参数一致）。
- **声明目的地已被移除**：它原本读的是卡车调度里**第一条**"在此被卸下"的车站，多个卸货计划时只有第一个有效、指代不清（"只装载去下一站的道路载具"开关已覆盖常见用法）。架构上仍保留"只装去下一站的车"（`ORVTF_MATCH_DEST`）。
- 窗口里的改动立刻写进订单；**订单行**会同步列出生效的设置（例如 `去 A 站 装载道路载具 只装载去下一站的道路载具 载具条件：仅空车 最短等待：5 天 最多 2 辆`）。
- 窗口在订单被删改、车辆被销毁时自行关闭。

> 早期版本把这些选项直接塞在下拉里，结果"载具条件 / 最短等待"两行出现了 `(invalid parameter)`——原因是我给 `{STRING}` 参数传了已格式化的字符串，而引擎只接受 StringID；改成收进独立窗口后这类嵌套参数整个不再需要。同时修掉了"窗口能打开但下拉点不动"（OpenTTD 里下拉控件必须在 `OnClick` 里自己 `ShowDropDownList`，我最初只处理了关闭按钮）。

**手测要点**：设一条明显不匹配的条件（例如 `仅空车`，而你的卡车正载着货；或 `最短等待 100 天`），然后让火车来装车——期望**装不上**（卡车继续等待）；把条件改回 `任意`/`不限` 后应当能装。全程无断言/崩溃。
