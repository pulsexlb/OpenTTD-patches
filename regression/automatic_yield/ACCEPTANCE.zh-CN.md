# PXP 自动待避强制验收清单

上位规范：仓库根目录 `AGENTS.md`。本清单适用于每次 PXP 开发任务结束，不限于修改自动待避代码的任务。

## 2026-11-01 增补：行驶中连接方向与无车头车厢看板

- 新连接认领出现时，正在行驶的机车仍必须比较前后方向；使用原生制动和停止后换向，不能等驶到线路尽头才纠正，也不能强制把运行速度写为零。一次认领只在原生重试间隔内完成一次行驶方向检查；新认领及取消必须更新该状态，停住后的原生 PBS 重试不受影响。覆盖刚解挂、车辆段、禁止途中换向、无目标及失效目标。
- 在原图中记录原生制动、实际停车、换向后的行驶及连接原始等待车厢。制动期间保存重载后应继续完成，不得重复方向摇摆。性能检查不得重新引入无目标时的逐刻全网搜索。
- `departures_primary.py` 加载真实存档，用真实出发面板验证具有独立调度、但位于物理链中间的逻辑主车。检查无车头车厢仅收集一次，实时及 24 小时模式的实际显示、车次、保存重载和 RNG 不变。参数包含公司、车号、车站，生产代码不能依赖这些测试输入。
- 实时看板默认前 20 条限制仍有效。必须区分“车辆未进入候选列表”和“其发车时间未进入前 20 条”；增加显示数量后验证后者，不能因收集成功就虚报默认窗口已经显示该行，也不能擅自取消原生数量上限。

## 执行顺序与证据

1. 完整编译并运行基础单元测试，记录构建身份与命令。
2. 运行自动待避核心原生行驶回归；先核实进线、停车、全部快车通过、恢复的完整阶段，发现阻断性回归立即优先处理。
3. 重放当前问题存档并运行任务专项测试，固定输入副本及校验值，不覆盖用户原文件。
4. 根据修改范围执行双制动模式、保存重载、服务器与至少两个客户端的同步及性能检查。
5. 按十项固定状态报告最终结果。不能自动验证时明确“未验证”，列出人工步骤。

现有 Windows/Ninja 驱动：

```powershell
python regression/automatic_yield/run.py --build-dir build-win64 --baseset <实际基础图形目录> --output <本次独立输出目录>
python regression/automatic_yield/run.py --build-dir build-win64 --baseset <实际基础图形目录> --output <本次常规制动输出目录> --braking 0
```

上述驱动是入口，不代表清单所有项目已实现。必须读取当前模式及断言，确认实际覆盖，不能仅统计 PASS 数量。其他平台使用项目现有构建方式；无法运行时注明原因。

## 准确速度与扩展场景

至少维护 100→200 和 100→连续 160／200／250 的真实运行输入。记录实际设计速度及检测上限，不能把接近速度的原版机车当成准确速度，不能强改运行速度或停车状态来通过。既有修改引擎规格的满线隔离用例不替代该核心要求。

还须覆盖长距离目标、远处接近列车、停站前后目标切换、晚到快车、装卸、不同公司、前／尾／预留登记、满线安全腾位、保存等待状态后加载，以及调度修改、改道、删除、手动取消登记后的正确生命周期。必要时增加对应模式与日志断言。

## 无法自动验证时的人工步骤

1. 在启用自动待避的副本中，用真实设计速度分别为 100、160、200、250 的车辆搭建一正线一侧线及同一路签的四项控制点。
2. 启动慢车和跟随快车，记录进侧线、全列清空入口道岔、在出口停车、每列快车实际通过、最后车尾出清及慢车恢复的顺序；在等待中保存重载。
3. 分别换成全站台、普通、混合、非对称及多入口出口布局，增加串联正线及出口信号，测试汇合、分流和再汇合。
4. 运行中新增一条可达侧线／连接道岔，再安全删除或改接空闲支线；分别在有、无旧合法预留时观察候选与实际选路。不得人工非法清除预留强迫选新路。
5. 使侧线满载，观察安全腾位和恢复；用同一构建开本机服务器与两个客户端，重放保存点并比较状态。记录未覆盖项及具体失败事件。

人工步骤仅供执行，不等于已经验证；未实际执行的项目仍标记“未验证”。

平台可达性、站台容量疏解、未知邻近进路和有效保存依赖均保留独立测试。修改夹具原生区间或准确速度时必须说明原因，原版 112 或改过规格的 100 不得冒充准确 100 的专用原生场景。

真实问题存档仍须单独重放。207/205、309/310 的历史分岔决策已不在保存点中；相同真实车辆、调度和原站场的原生克隆运行属于等价复现，必须明确标注，不能冒充历史录像。

- 运行 `early_route_driving.py`，与原有 `run.py` 完整矩阵共同验收；说明见 `early_route_cases.zh-CN.md`。单出口的96份受保护阶段日志须与修改前一致，不能只核对最终 PASS。

- 调度修改测试必须记录变更时的实际 PBS 末端与分岔预留。已经越过分岔的合法预约不能被测试强制撤销；此时的原生掉头恢复须另列验证。
- 联机指纹必须包含完整计划数组及区域上下文，不能只比较车速和位置。保存、客户端加入、局部轨道施工后分别检查三端一致性。

- 新沙下行 204/205 类相邻弯轨分流：不能把道岔上不同轨道具有相同退出方向，误当作沿同一有向股道追踪。必须检查两条完整已选进路的所有资源，而不是仅看首个交叠点；快车车尾移动、首个交点改变时不能恢复失效依赖。新增 `split-crossing` 实车新开局／重载门槛；原有正交交叉、真实共线、分流后再合流及单待避站断言不得修改。不同出口本身不能作为独立性的证明。
- 吕梁下行 87/66 类多普通侧线、单正线单出口：必须比较独立查询与实际 YAPF／PBS 信号回调中的识别结果。不能以独立查询 `NeedsSiding=true` 冒充真实预约时已阻止直行；记录实际回调的快车距离、预算和可用停车证明。只调整检查额度分配时仍须保持总上限，并重新验证站台高惩罚回退、单侧线及多出口原规则。玩家原图应验证整列进入、出口停车、真实车尾出清、恢复、路签释放，以及等待中读档后的相同完整过程。

- `split-alternative` 在同一目的地下提供短共用咽喉和较长独立线路，不改原生成本、速度或引擎。新版本必须实际采用独立连接并到达原目标；旧版只等快车后走原咽喉不能通过。既有无独立替代的进线/停车/清尾/恢复断言保留。
- 只在多出口双方完整真实进路、不同出口且已有侧线认领时请求一次新搜索。记录证据不能修改正在运行的A*过滤器；本车合法已预约的有向点不能排除。新搜索也必须经过正常PBS申请，失败不发布新计划，不清除旧等待。
- restricted PBS早退发生在YAPF之前，不能只测试YAPF内部重试；实际车辆必须经过外层决策、原生预约、移动及目标到达验证。显式换向、已成功预约和单出口不得走新重试。
- 联机指纹以原生网络帧配对，游戏刻仍须混入指纹。暂停时游戏刻不变，但客户端加入/创建公司仍执行网络命令、改变RNG和校验；不能把不同网络帧的同一游戏刻误判为不同步，也不能简单丢弃暂停样本或忽略随机数。记录并比较共同网络帧的全部字段。

## 2026-11-06 增补：侧线提前出线与运行中资源刷新

- 王家上行 161/102 类故障：同一实际出口、没有既有等待目标的站台或普通侧线发车，不能仅以越过 PXP Clear 的时间证明可安全抢先出线。还必须证明整列能够释放相关原生信号区间，并计入起步速度；沿用现有安全腾位的只读区间证明，不能撤销 PBS。
- 保留真正远处快车之前的安全普通发车，以及既有 32 格等速腾位边界。候选方向分类的共享软额度不得吞掉已经确认冲突之后的出线证明；相同车辆对和认领状态的风险证明仅在本次评估中复用，不增加每次评估的总扫描上限、不持久化缓存。
- 单元门槛：`Automatic yield departure - clearing the area marker is not releasing the express native block` 必须在旧实现上失败、修复实现上通过；原远处快车和等速腾位测试的预期不能改低。

- 连挂后运行中刷新 NewGRF：`AfterLoadVehiclesPhase1(false)` 必须保存刷新前的实时逻辑主车辆，不能用上次保存遗留的主车辆标记重建。覆盖逻辑主车辆处于链中部、纯车厢、认领与接触目标保持、连续刷新及再次改变编组；真实存档验证接近、正常减速、连挂和无撞车。正常读档仍使用存档标记，不能将运行中刷新修复冒充事故后车辆恢复。

## 解挂独立计时选项（2026-11-06）

运行 `decouple_timing.py`，必须检查第一／第二部分独立选择、默认关闭、直接切换计划、装卸后切换计划、保持原计划及无效计划。通过真实到站解挂验证：只有成功切换计划且已勾选的部分归零历史早晚点；继续原计划部分的计时与车厢车次保持不变。后续停车路点仍按新计划等待并实际发车，不能通过跳过命令或强制停车验证。包含命令查询不修改状态、非法数值拒绝，以及开关的存档重载。

指定发车时刻使用的计时不能被当作历史早到清除；多人联机须通过原生命令设置选项并比较解挂前后的计时、车辆链及 PBS 状态。新存档 `order_decouple` 功能版本为 2，旧存档按默认关闭载入；旧程序应拒绝未知版本，不能静默忽略新选项。

## 解挂共享发车表只领一次班次（2026-11-06）

运行 `service_driving.py` 的 `split-dispatch-shared`、`split-dispatch-shared-both`、`split-dispatch-shared-schedule`，包含正常行驶和读档。必须检查同一次到站的共享计划只推进一个发车周期，车厢保留车次和正确时刻；两部分都装卸时取得相同班次，到点前保持停车，到点后有动力部分实际驶离。独立调机计划不能额外消耗运输计划的下一班。
