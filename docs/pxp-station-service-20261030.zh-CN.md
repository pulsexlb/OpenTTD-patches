# 按停站命令换车次与解挂继承（2026-10-30）

本版替代此前“时刻表设置本车固定车次”的界面。设置入口已移到**调度计划**，时刻表不再提供车次设置入口。

## 使用

选中一条真正停站的“前往车站”命令，在下方车次栏选择：

- **本站不更换**：沿用正在运行的车次。
- **设置本站出发车次……**：输入例如 G123，本站到达时切换，本站出发看板提前显示 G123。下一站可另设 G456。
- **使用计时调度车次**：本站出发采用计时调度发车时刻对应的车次，与手动车次互斥；原有发车时刻车次定义保留。

命令行标注各站出发车次。共享调度计划共用这些设置。跳过停站的“经由”命令、路点和车辆段不能设置此字段。取消输入不修改；清空手动输入表示本站不更换。打开输入框后改选其他行，不会将输入错写到新选中的车站；原订单被移除或更换后放弃失效输入。

有有效车次时，出发看板显示车次并隐藏载具名称；无车次时按原选项显示名称。默认显示载具名称的看板无需另开计时调度车次显示选项。载具标题原有“显示车次”选项保留。

## 解挂与重新连挂

解挂完成后，带普通车厢的部分保留车次，纯机车部分清除，不从旧计时调度记录恢复显示。两部分都带车厢时，各自保留。机车重新连挂有车次的车厢且自身无有效车次时，采用车厢的号码。之后到达明确配置新车次的车站，仍按新命令换号。

内部身份仍由原生主车辆承载；“随车厢”指解挂后的身份归属，不会拆散铰接组、移动动力端或改写车辆链结构。

## 实现和保护范围

- `OrderExtraInfo` 保存本站来源模式和号码，随订单复制、共享、JSON 导入导出和存档保存。
- `CmdSetOrderServiceNumber` 使用原生同步命令，验证目标、公司、停站类型、索引、模式和长度。编辑未来车站不提前换号；已在该站装卸时修改，会更新当前号码。
- `Vehicle::ApplyStationServiceNumber` 在真实到站时应用；看板采用本站出发配置。直线订单片段可逐站推算沿用值；遇条件跳转或子计划，不提前执行有副作用的调度或假定未知分支。重要换号站应明确设置本站车次。
- 实际解挂及装卸状态建立后分配身份；纯机车使用持久抑制位，避免旧 dispatch_records 又显示旧号码。到站选槽后读取实际记录的计时调度号码。
- `BaseConsist` 的属性复制和订单备份保留字段。独立存档标记 `pxp_fixed_service_number` 升至 v2；v1 固定车次存档继续读取。新存档需要支持 v2 的程序，联机各端须同版。
- 原有命令编号保留，新订单设置命令追加。没有修改连挂选车、解挂切点、车辆方向、PBS 预约、自动待避优先级或满线放行规则。

## 手工复核

1. 在调度计划选中甲站，设 G123；选中乙站，设 G456。命令行应标注对应号码，时刻表应无车次入口。
2. 列车到站前查看两站出发看板，应分别显示各站的新号码。到站后实际号码依次切换。
3. 在甲站按合法切点分离机车和车厢：机车不保留号码，车厢保留；重新连挂后恢复。
4. 切换某站为计时调度来源，确认不会同时显示手动车次；保存重载后重复检查。
